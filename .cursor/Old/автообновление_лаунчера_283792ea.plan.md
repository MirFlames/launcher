# План реализации автоматических обновлений лаунчера

## Архитектура решения

Система автообновления будет состоять из четырех основных компонентов:

1. **Backend API** - расширение существующего Go сервера для предоставления информации о версиях лаунчера и JDK
2. **Launcher:**

**2.1. Модуль Updater** - отдельный процесс для проверки и установки обновлений лаунчера

**2.2 Launcher** - встроенная проверка обновлений лаунчера, автообновление JDK, запуск игры

1. Игра - черный ящик, java-приложение запускаемое лаунчером.

## Подход: Отдельный updater-процесс (как Chrome/Firefox)

**Преимущества:**

- Безопасная замена исполняемого файла (основной процесс не блокирует свой exe)
- Возможность отката при ошибках
- Простота реализации
- Работает с native-image exe файлами

## Компоненты реализации

### 1. Расширение Backend API (`backend/main.go`)

#### 1.1. Endpoint для версий лаунчера

Добавить новый endpoint для информации о версиях лаунчера:

```go
GET /api/launcher/version
```

**Ответ:**

```json
{
  "version": "1.0.1",
  "download_url": "https://example.com/launcher/launcher-1.0.1.exe",
  "hash": "sha256:abc123...",
  "size": 12345678,
  "release_notes": "Исправлены баги...",
  "mandatory": false
}
```

#### 1.2. Endpoint для JDK (критически важно)

Добавить endpoint для информации о требуемом JDK:

```go
GET /api/jdk/info
```

**Ответ:**

```json
{
  "version": "jdk-21.0.2",
  "relative_path": "jre_default\\jdk-21.0.2",
  "java_executable": "bin\\java.exe",
  "mandatory": true
}
```

**Важно:**

- `version` в формате `jdk-21.0.2` (используется для определения папки и запроса к Adoptium API)
- `relative_path` - относительный путь от папки Minecraft (где находится launcher.exe)
- Полный путь будет: `{minecraftFolder}/{relative_path}`
- **Скачивание JDK происходит через Adoptium API**, а не через `download_url` из backend
- Backend конфиг содержит только информацию о требуемой версии, не URL для скачивания

**Изменения:**

- Добавить модель `LauncherVersion` и `JDKInfo` в `backend/models.go`
- Добавить handlers `handleLauncherVersion` и `handleJDKInfo` в `backend/main.go`
- Добавить конфигурацию версии лаунчера и JDK в `backend/config.json`

### 2. Updater модуль (`updater/`)

**Вариант A: Java updater (рекомендуется)**

- Использует те же библиотеки (Jackson, HTTP клиент)
- Легко интегрируется с существующим кодом
- Компилируется в отдельный `updater.exe` через GraalVM

**Вариант B: Go updater**

- Легковесный, быстрый
- Простая сборка для Windows
- Меньше зависимостей

**Функциональность updater:**

1. **Проверка закрытия лаунчера** (критически важно!)
  - Проверка процесса launcher.exe через ProcessHandle/GetProcessesByName
  - Ожидание до 10 секунд с периодической проверкой
  - Если процесс не закрылся - ошибка и выход
2. Скачивание нового exe в временную директорию (`%TEMP%/launcher-update/`)
3. Проверка SHA-256 хеша скачанного файла
4. Создание резервной копии: `launcher.exe.backup`
  - **Если бэкап уже существует - перезаписать его**
5. Замена старого exe новым файлом
6. **Попытка запуска обновленного лаунчера** (через ProcessBuilder/exec.Command)
7. **Обработка ошибок:**
  - Если запуск не удался - удалить обновленную версию
  - Восстановить из `launcher.exe.backup`
  - Показать сообщение об ошибке пользователю
8. Очистка временных файлов (при успехе)

**Параметры командной строки updater:**

- `--launcher-path <path>` - путь к launcher.exe для обновления
- `--update-url <url>` - URL для скачивания нового launcher.exe (опционально, если не указан - запрашивает через API)
- `--api-url <url>` - URL backend API для проверки версий (опционально)

**Обработка ошибок скачивания:**

- **Недоступность сервера лаунчера:** Показать ошибку "Недоступен сервер обновлений лаунчера" и закрыться
- **Недостаточно места на диске:** Показать ошибку "Недостаточно места на диске" и закрыться
- **Ошибка сети:** Показать ошибку "Ошибка доступа к интернету" и закрыться
- Не повторять попытки автоматически
- Не сохранять частично скачанные файлы

**Структура:**

```
updater/
├── src/main/java/com/launcher/updater/
│   ├── UpdaterMain.java          # Точка входа, парсинг аргументов
│   ├── UpdateChecker.java        # Проверка версий через API
│   ├── UpdateDownloader.java     # Скачивание и проверка
│   ├── UpdateInstaller.java      # Замена exe файла и запуск лаунчера
│   └── UpdateConfig.java         # Конфигурация (URL API, пути)
└── build.gradle                  # Сборка updater.exe
```

### 3. JDK Manager - Автоматическая установка JDK

**Проблема:** Пользователь не должен самостоятельно устанавливать JDK, но для запуска Minecraft требуется именно JDK (не JRE).

**Важное требование:** Папка Minecraft определяется **строго по расположению исполняемого файла** `launcher.exe`. Если exe находится в `C:\Games\Minecraft\`, то это и есть папка Minecraft.

**Решение:** Автоматическая загрузка и установка portable JDK при первом запуске лаунчера в папку Minecraft (где находится launcher.exe).

**Добавить класс `JDKManager.java`:**

- **Определение папки Minecraft:** По расположению исполняемого файла `launcher.exe` (директория, где находится exe)
- **Расположение конфига:** `{minecraftFolder}/configs/minecraft-launch-config.json`
- **Проверка наличия JDK:** Путь вычисляется как `{minecraftFolder}/jre_default/{jreVersion}/bin/java.exe`
  - Например: если exe в `C:\Games\Minecraft\launcher.exe`, а jreVersion = "jdk-21.0.2" (из backend конфига), то путь будет `C:\Games\Minecraft\jre_default\jdk-21.0.2\bin\java.exe`
- Если JDK отсутствует или версия отличается от требуемой:
  - Запрос информации о JDK через `/api/jdk/info` (получает версию в формате `jdk-21.0.2` и `relative_path`)
  - Вычисление полного пути: `{minecraftFolder}/{relative_path}`
  - **Скачивание JDK через Adoptium API** (не через backend download_url)
  - Скачивание ZIP архива JDK в `%TEMP%/launcher-jdk/`
  - Проверка SHA-256 хеша (если доступен)
  - Распаковка в `{minecraftFolder}/jre_default/{jreVersion}/`
  - **Не удалять старую версию JDK** (оставить для возможности ручного удаления пользователем)
  - Проверка работоспособности (`java -version`)
  - Обновление конфига `minecraft-launch-config.json` с правильным путем к `java.exe` (абсолютный путь)
- Кэширование: JDK устанавливается в папку Minecraft, используется при всех последующих запусках
- **Универсальный прогресс-бар** при установке JDK (будет использоваться для модов и версий игры в будущем)
- **Блокировка запуска игры** во время обновления JDK
- **Нельзя отменить** установку JDK

**Структура:**

```
launcher/src/main/java/com/launcher/
├── JDKManager.java              # Управление JDK
├── JDKDownloader.java           # Скачивание JDK архива
├── JDKInstaller.java            # Распаковка и установка
└── JDKVerifier.java            # Проверка установленного JDK
```

**Изменения в `MinecraftConfigLoader.java`:**

- **Определение папки Minecraft:** По расположению исполняемого файла `launcher.exe` (директория exe)
- **Путь к конфигу:** `{minecraftFolder}/configs/minecraft-launch-config.json`
- Загрузка конфига из этой папки
- Передача `minecraftFolder` в `JDKManager` для определения пути к JDK
- Автоматическое определение пути к JDK через `JDKManager.getJDKPath(minecraftFolder)`
- Fallback на путь из конфига, если JDK уже установлен

**Изменения в `MinecraftLauncher.java`:**

- Вызов `JDKManager.ensureJDKInstalled()` перед запуском Minecraft
- Обработка ошибок установки JDK (показ сообщения пользователю)

### 4. Интеграция в Launcher (`launcher/src/main/java/com/launcher/`)

**Добавить класс `UpdateManager.java`:**

- **Проверка обновлений при каждом запуске** (обязательно, перед инициализацией UI)
- **Принудительное обновление:** Если найдено обновление - лаунчер не запустится пока не обновится
- Запуск updater.exe если найдено обновление
- **Информационное уведомление** по факту завершения обновления (не требует согласия, просто информирует)
- **Обработка отсутствия интернета/недоступности сервера:**
  - Показать ошибку: "Не удалось подключиться к серверу обновлений"
  - После нажатия ОК - закрыть лаунчер (`System.exit(1)`)
  - Не кэшировать ответы сервера
- **Хранение версии лаунчера:** Жестко закодирована в `Consts.LAUNCHER_VERSION` (обновляется при сборке нового exe)

**Изменения в `LauncherFrame.java`:**

- **Блокировка запуска нескольких экземпляров** `launcher.exe` (проверка при старте)
- Добавить проверку обновлений в `main()` **перед** инициализацией UI
- Если найдено обновление - запустить updater и закрыться (не показывать UI)
- Если обновлений нет - продолжить инициализацию UI
- Показывать информационное уведомление после завершения обновления (если обновление было)

### 5. Механизм обновления

**Общий процесс (синхронизация):**

1. **Установка:** Инсталлер устанавливает `launcher.exe` и `updater.exe` в выбранную папку (оба exe, не требуют JRE, собраны через GraalVM native-image)
2. **Проверка обновлений:** При запуске лаунчер проверяет наличие обновлений через API
3. **Обновление:** Если найдены обновления:
  - Лаунчер запускает `updater.exe` с параметрами и закрывается
  - Updater проверяет, что лаунчер закрылся
  - Updater делает бэкап и обновляет лаунчер
  - Updater пытается запустить новый лаунчер
  - При ошибке: удаляет обновленную версию и восстанавливает бэкап

**Детальный процесс:**

1. Лаунчер запускается, **проверяет версию через API** (обязательно при каждом запуске)
2. **Если нет интернета или сервер недоступен:**
  - Показать ошибку: "Не удалось подключиться к серверу обновлений"
  - После нажатия ОК - закрыть лаунчер (`System.exit(1)`)
3. Если найдено обновление:
  - **Принудительное обновление:** Лаунчер не запустится пока не обновится
  - Запускает `updater.exe` с параметрами:

```
     updater.exe --launcher-path "C:\Games\Minecraft\launcher.exe" --update-url "https://..."
     

```

- Закрывает лаунчер (System.exit(0))
- **Важно:** Лаунчер должен закрыться ДО того, как updater попытается заменить exe файл

1. После обновления (когда updater запустит новый лаунчер):
  - Показать **информационное уведомление** о завершении обновления
  - Уведомление не требует согласия - просто информирует пользователя
2. Updater (после запуска от лаунчера):
  - **Проверяет, что лаунчер закрылся** (ждет до 10 секунд, проверяя процесс)
  - Если лаунчер не закрылся - показывает ошибку и завершается
  - Скачивает новый exe в `%TEMP%/launcher-update/`
  - Проверяет SHA-256 хеш скачанного файла
  - Создает резервную копию старого: `launcher.exe.backup`
  - Заменяет `launcher.exe` новым файлом
  - **Пытается запустить новый лаунчер** (см. детали ниже)
  - **В случае ошибки запуска:** удаляет обновленную версию и восстанавливает из `launcher.exe.backup`
  - Удаляет временные файлы

**Механизм запуска лаунчера после обновления:**

Updater получает путь к `launcher.exe` как параметр командной строки при запуске от лаунчера:

```
updater.exe --launcher-path "C:\Program Files\Launcher\launcher.exe" --update-url "https://..."
```

**Процесс запуска:**

1. **После успешной замены файла:**
  - Updater определяет путь к launcher.exe (из параметра или автоматически, если в той же директории)
  - Использует `ProcessBuilder` (Java) или `exec.Command` (Go) для запуска
  - Запускает процесс в **отдельном процессе**, не блокируя updater
2. **Реализация (Java вариант):**

```java
   ProcessBuilder pb = new ProcessBuilder(launcherExePath);
   pb.directory(new File(launcherExePath).getParentFile());
   pb.start(); // Запуск в фоне, не ждем завершения
   

```

1. **Реализация (Go вариант):**

```go
   cmd := exec.Command(launcherExePath)
   cmd.Dir = filepath.Dir(launcherExePath)
   cmd.Start() // Запуск в фоне
   

```

1. **После запуска:**
  - Updater может сразу завершиться (не ждет завершения лаунчера)
  - Или подождать 1-2 секунды для проверки успешного запуска
  - Если лаунчер не запустился - показать ошибку и предложить откат
2. **Обработка ошибок запуска:**
  - После попытки запуска проверить успешность (подождать 2-3 секунды, проверить процесс)
  - Если запуск не удался:
    - Удалить обновленную версию `launcher.exe`
    - Восстановить из резервной копии: переименовать `launcher.exe.backup` → `launcher.exe`
    - Показать сообщение об ошибке пользователю
    - Логировать ошибку в файл для отладки
  - Если запуск успешен - удалить резервную копию (опционально, можно оставить для безопасности)

**Альтернативный подход (более надежный):**

Использовать промежуточный batch-скрипт для запуска:

- Updater создает временный `.bat` файл
- Скрипт запускает launcher.exe и удаляет себя
- Updater запускает `.bat` и завершается
- Преимущество: гарантирует запуск даже если updater завершится раньше

**Безопасность:**

- Проверка SHA-256 хеша скачанного файла
- Валидация размера файла
- Резервная копия для отката
- Проверка целостности после замены

**Важные детали реализации:**

1. **Проверка закрытия лаунчера (критически важно!):**
  - Windows не позволяет удалить/заменить exe файл, если он запущен
  - Лаунчер закрывается перед запуском updater
  - **Updater ОБЯЗАТЕЛЬНО проверяет**, что процесс launcher.exe закрылся
  - Реализация проверки:
    - Java: `ProcessHandle.allProcesses().filter(...)` или через `tasklist` команду
    - Go: через `os.FindProcess()` или `exec.Command("tasklist")`
  - Ожидание до 10 секунд с проверкой каждые 500мс
  - Если процесс все еще запущен после ожидания - показать ошибку и завершиться
  - Только после подтверждения закрытия - начинать замену файла
2. **Порядок операций:**
  - **Блокировка нескольких экземпляров:** Проверка при старте, если уже запущен - закрыться
  - Лаунчер проверяет обновления при запуске (обязательно, при каждом запуске)
  - **Если нет интернета/сервер недоступен:** Показать ошибку, после ОК - закрыть лаунчер
  - Если найдено обновление: **принудительное обновление** (лаунчер не запустится)
    - Лаунчер запускает `updater.exe` с параметрами
    - Лаунчер закрывается (`System.exit(0)`)
  - Updater запускается и **проверяет закрытие лаунчера** (всех экземпляров)
  - После подтверждения закрытия:
    - Скачивает новый exe
    - Проверяет хеш
    - Создает бэкап (`launcher.exe.backup`, перезаписывает если существует)
    - Заменяет `launcher.exe`
    - Пытается запустить новый лаунчер
    - **При ошибке запуска:** удаляет обновленную версию, восстанавливает бэкап
  - Updater завершается
  - Новый лаунчер показывает **информационное уведомление** о завершении обновления
3. **Рабочая директория:**
  - При запуске нового лаунчера важно установить правильную рабочую директорию
  - Использовать директорию, где находится launcher.exe
  - Это важно для корректной работы путей к конфигам и ресурсам

### 6. Конфигурация

**Добавить в `backend/config.json`:**

```json
{
  "launcher_version": "1.0.1",
  "launcher_download_url": "https://example.com/launcher/launcher-1.0.1.exe",
  "launcher_hash": "sha256:...",
  "launcher_size": 12345678,
  "launcher_mandatory": false,
  "jdk": {
    "version": "jdk-21.0.2",
    "relative_path": "jre_default\\jdk-21.0.2",
    "java_executable": "bin\\java.exe"
  }
}
```

**Константы в лаунчере:**

- **Версия лаунчера:** Жестко закодирована в `Consts.LAUNCHER_VERSION` (обновляется при сборке нового exe)
- **API URL для проверки обновлений:** 
  - На данный момент жестко закодирован в `Consts.java`
  - **Требуется доработка:** Переход на хранение в конфиг-файле для разделения dev/prod окружений
  - Конфиг должен находиться в `{minecraftFolder}/configs/launcher-config.json`
- **Путь к updater.exe:** Всегда в той же папке что и `launcher.exe` (рядом с exe)
  - Если `updater.exe` отсутствует - **фатальная ошибка:** "Отсутствует агент автообновления. Переустановите лаунчер."
- **Папка Minecraft:** Определяется по расположению исполняемого файла `launcher.exe`

### 7. Сборка и распространение

**Gradle задачи:**

- `updater:build` - сборка updater.exe
- `launcher:build` - сборка launcher.exe
- `distZip` или `distTar` - создание дистрибутива с обоими exe

**Установщик должен:**

- Устанавливать `launcher.exe` и `updater.exe` в одну директорию (выбранную пользователем)
- **Папка Minecraft = папка где установлен launcher.exe** (определяется автоматически)
- Создать структуру папок: `{installDir}/configs/` для конфигурационных файлов
- Оба exe файла собираются через GraalVM native-image (не требуют JRE)
- Создавать ярлыки на рабочем столе и в меню Пуск
- Регистрировать в системе (опционально)
- **НЕ включать JDK в установщик** - JDK будет скачиваться автоматически при первом запуске в папку Minecraft

**Подготовка JDK для распространения:**

- Backend конфиг указывает требуемую версию JDK (например, `jdk-21.0.2`)
- **Скачивание JDK происходит напрямую через Adoptium API** (не через backend)
- Лаунчер использует Adoptium API для получения download_url и скачивания JDK
- Backend конфиг содержит только информацию о требуемой версии и `relative_path`

## Решение проблемы JDK

### Проблема

Пользователь не должен самостоятельно устанавливать JDK, но для запуска Minecraft требуется именно JDK (не JRE). Это строгое требование.

### Решение: Автоматическая установка Portable JDK

**Подход:** Лаунчер автоматически скачивает и устанавливает portable JDK при первом запуске.

**Преимущества:**

- Пользователь не должен ничего устанавливать вручную
- Полный контроль над версией JDK
- Изолированная установка (не конфликтует с системным Java)
- Возможность обновления JDK через backend API

**Процесс:**

1. При первом запуске лаунчер:
  - Определяет `minecraftFolder` по расположению исполняемого файла.
  - Проверяет наличие JDK по пути `{minecraftFolder}/jre_default/{jreVersion}/bin/java.exe`
  - Например: если exe файл запущен из `"C:\Games\Minecraft"`, а jreVersion = "jdk-21.0.2" (берется из файла конфигурации), то путь будет `C:\Games\Minecraft\jre_default\jdk-21.0.2\bin\java.exe`
2. Если JDK отсутствует или версия отличается от требуемой:
  - Показывается **универсальный прогресс-бар** "Установка JDK..." (блокирует запуск игры)
  - Запрос информации о JDK через `/api/jdk/info` (получает версию в формате `jdk-21.0.2` и `relative_path`)
  - Вычисление полного пути установки: `{minecraftFolder}/{relative_path}`
  - **Скачивание ZIP архива JDK через Adoptium API** (порядка 200-300 МБ) в `%TEMP%/launcher-jdk/`
  - Проверка SHA-256 хеша (если доступен от Adoptium API)
  - Распаковка в `{minecraftFolder}/jre_default/{jreVersion}/`
  - **Не удалять старую версию JDK** (оставить для возможности ручного удаления)
  - Проверка работоспособности (`java -version`)
  - Обновление `minecraft-launch-config.json` с правильным путем к `java.exe` (абсолютный путь)
  - **Нельзя отменить** установку JDK
  - **При ошибке установки:** Отобразить ошибку пользователю
3. При последующих запусках JDK используется из кэша

**Требования к JDK на момент написания ТЗ:**

- Portable версия (ZIP архив, не установщик)
- Windows x64
- Версия 21 (или требуемая для Minecraft)
- Рекомендуется: Eclipse Temurin или Adoptium (бесплатные, проверенные)
